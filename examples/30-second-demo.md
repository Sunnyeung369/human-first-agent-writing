# 30 秒演示

这是一条最小提示词。把它交给支持 Skill 的 Agent，观察它是否先确认读者和目标，再按“研究 → 起草 → 人味编辑 → 事实核查”给出结果。

```text
请为第一次接触这个主题的小团队创始人写一段 300 字说明。
主题：为什么小团队应该先改进一个高频流程，再考虑部署多 Agent。
要求：
1. 先列出需要核实的事实；没有来源的内容标为判断。
2. 写一版具体、有取舍的初稿，避免“在当今时代”“赋能”“全面提升”等套话。
3. 编辑一遍，让句子有长有短，保留一个反例。
4. 最后列出仍然不确定的地方。
```

## 你应该看到什么

- 简单任务不会强行调用全部角色。
- 事实、判断和建议分开。
- 编辑会删掉空泛句子，而不是把文本改得浮夸或故意口语化。
- 如果宿主没有搜索或并发能力，Agent 会明确说出来。

这不是性能基准，也不保证每个模型都在 30 秒内完成；“30 秒”指从复制提示词到看见第一版工作流反馈的目标体验。
